# QA report

Tested against a **production build** (`next build` + `next start`) with `DASHBOARD_PASSCODE` set and the **file store**, driven by Playwright/Chromium. Final run: **63 of 63 checks passed**, plus checks below.

## Repo checks

| Check | Result |
|---|---|
| `npm run lint` | clean |
| `npm run build` | passes; `/dashboard/*` routes present as dynamic |
| `npm run typecheck` | passes (run after build; `LayoutProps` types are generated by the build, which is pre-existing behaviour) |
| `scripts/check-campaign.ts` | 56 episodes, 168 clips, 224 pieces, day 1 = 2026-11-06, day 56 = 2026-12-31, every clip has 3 hooks + point + visual + screen recording + overlays + CTA, **no duplicate hooks**, ≤ 1 client-CTA clip per day |

## Functional (all passed)

- **Access:** unauthenticated `/dashboard` → redirected to login; unauthenticated API `GET`/`PATCH` → 401; wrong passcode rejected; correct passcode opens the dashboard.
- **Overview:** shows "Day 1 of 56" (test date 2026-11-06), the three targets, today's episode; entered totals (12 / 34) appear on the scorecards; a lead marked Won shows **1 / 3** paid projects.
- **Calendar:** 56 episodes render; chapter filter works (Ch 7 → 10 episodes); setting TikTok 2 to *Editing* persists after reload **and the other three pieces stay independent**.
- **Episode workspace:** brief edit saves, shows an "Edited" badge, and persists; **Reset to plan** restores the original; script autosaves and persists, and moves the YouTube status to *Script written*; checklist ticks persist.
- **Performance:** daily numbers (incl. blank-field handling) save and persist; totals feed the overview.
- **Leads:** create, edit status, delete (with confirm); persisted across reloads. **Notes:** create, persist, delete.
- **Persistence across a server restart:** statuses, scripts and totals were still present after restarting the server.
- **Responsive:** no horizontal page overflow on 7 dashboard pages at phone (390×844), tablet (820×1180) and desktop (1440×900). Screenshots were reviewed visually for the overview, calendar and an episode.

## Security (all passed)

- Cross-origin write (`Origin: https://evil.example`) → **403**. Non-JSON write → **415**. Unknown collection → **400**. Path-traversal-style id → **400**.
- **A Growth Operator System session (free name+email signup) cannot open `/dashboard`**, and `/growth-system` itself still works.
- **Fail-closed, no passcode set:** login page says the dashboard is locked; any passcode, including an empty one, is rejected; `/dashboard` redirects to login.
- **Production with a passcode but no database:** the orange "nothing will be saved" banner shows; a status change returns a visible error and the control **reverts** instead of pretending to save; no file is written.

## Existing site (unchanged)

`/`, `/about`, `/book`, `/what-we-build`, `/work`, `/contact`, `/growth-system`, `/robots.txt` return 200; the homepage keeps its marketing nav; the growth-system signup and its dashboard still work; marketing header/footer are hidden only under `/dashboard`; `robots.txt` now disallows `/dashboard`. No existing component other than `SiteChrome` and `middleware.ts` was edited, and the `/growth-system` middleware branch is untouched.

## Bugs found and fixed during QA

1. **Phone overflow on Overview (97 px):** grid cards had no `min-w-0`, so a non-wrapping row widened the column. Fixed in `Card`; re-verified.
2. **Brief editor would lose in-progress edits on re-render:** an inline component type remounted on every parent update. Replaced with a stable context-based component before it shipped.
3. **Content depth:** an audit showed 102 clips with thin points/closings or placeholder recording instructions (e.g. "None."), mostly Days 23–56. Rewrote them in depth layers; audit now reports 0 thin clips.
4. A failed test run was caused by a stale server on the same port after a rebuild, not by the app; re-run on a clean server.

## NOT tested / not verified

- **Supabase backend.** Written but **never executed**: no credentials in this environment, and I did not run the migration because the linked project holds Agriloop's production tables. Treat the first save against Supabase as untested.
- **Vercel deployment.** Nothing was deployed. Env vars have not been set. `/dashboard` is not live.
- **A real tablet.** Tablet = Chromium at 820×1180, not an iPad/Android device. Touch behaviour, on-screen keyboards, and tablet Safari quirks are unverified.
- Screen-reader and full keyboard accessibility audit (labels, roles, focus rings and 44 px targets were built in but not formally audited).
- Concurrent edits from two devices (last write wins at field level for deep merges; not stress-tested).
- Brute-force protection beyond a 600 ms delay.
- Platform analytics: not connected, by design.

## Known limitations

- Saving requires either a configured Supabase project or local development. Until then the deployed dashboard is read-only in practice.
- Briefs in Chapters 5–7 are somewhat leaner than Chapter 1 (roughly 375–430 vs 690 words/episode on average). They're complete and usable but benefit from your edits once you know what really happened.
- Many Chapter 3–7 episodes are **conditional** (client, call, deal, launch, Agriloop numbers). The brief says so; the facts must come from you.
- "Today" uses `DASHBOARD_TIMEZONE` (default `America/Jamaica`).
- No export of your own scripts/notes from the UI yet (the data is in the database/JSON file).
